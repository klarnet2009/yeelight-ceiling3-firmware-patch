# Руководство по сборке, проверке и OTA-развёртыванию

Процедура сборки модифицированной прошивки и её развёртывания на лампу `yeelink.light.ceiling3` (`YLXD17YL`, `2.0.2_0048`).

> [!CAUTION]
> **Прошивка никогда не запускается автоматически.** Любая команда `miio_ota.py flash ...` должна выполняться оператором вручную с осознанным подтверждением. При запуске без `--yes` скрипт останавливается и ждёт нажатия `Enter`.

---

## 1. Предварительная проверка (Pre-flight)

Перед сборкой и прошивкой проверьте все обязательные условия:

1. **Целостность стокового образа**:
   Файл yeelink.light.ceiling3-stock-2.0.2_0048.bin должен иметь размер `726978` байт и MD5 `13b7471a0f84e3cfbac78c116fae7a1c`:
   ```powershell
   Get-FileHash -Algorithm MD5 yeelink.light.ceiling3-stock-2.0.2_0048.bin
   ```
2. **Зависимости Python и `liblzma`**:
   - Наличие `C:\Program Files\Git\mingw64\bin\liblzma-5.dll` (или переменной окружения `LIBLZMA` на `liblzma >= 5.4`).
   - Установленные пакеты: `cryptography` (для `miio_ota.py`), `requests` и `qrcode` (дополнительно для `--cloud` и `xiaomi_qr_token.py`), опционально `capstone` (для дизассемблинга патчей при сборке).
3. **Токен устройства (`token.txt`)**:
   Файл `token.txt` должен содержать 32 hex-символа без лишних символов (только токен). При отсутствии или смене токена после сброса лампы получите его заново через QR-вход:
   ```powershell
   python xiaomi_qr_token.py de
   ```
   Проверьте связь с лампой (по умолчанию `--ip=192.168.0.20`):
   ```powershell
   python miio_ota.py info
   python monitor_lamp.py --once
   ```
   Убедитесь, что `model` равен `yeelink.light.ceiling3`, а статус `monitor_lamp.py` — `OK`.
4. **Доступность TCP-порта `80` на хосте**:
   Встроенный HTTP-клиент лампы `httpc_req` (`0x10100750`) не парсит `:port` из URL — он всегда подключается к порту `80` для `http://`. Поэтому локальный HTTP-сервер в `miio_ota.py` обязан слушать `0.0.0.0:80`.
   Проверьте, что порт `80` не занят (например, IIS, Apache, Docker, WSL-пробросом или Skype):
   ```powershell
   netstat -ano | Select-String ":80\s"
   ```
5. **Брандмауэр Windows (Inbound TCP 80)**:
   Лампа (`192.168.0.20`) будет скачивать `.bin` с IP этого ПК в той же подсети. Убедитесь, что в Windows Firewall разрешён входящий трафик на `TCP 80` от `192.168.0.20` (или для профиля Private/Domain сети). Если правило отсутствует, создайте его с правами администратора:
   ```powershell
   New-NetFirewallRule -DisplayName "Yeelight OTA HTTP 80" -Direction Inbound -Protocol TCP -LocalPort 80 -RemoteAddress 192.168.0.20 -Action Allow
   ```

## 2. Сборка и верификация образов

1. **Этап А — переупаковка стока без патчей (проверка конвейера LZMA/MMM)**:
   ```powershell
   python patch_ota.py --stock
   ```
   Результат: `yeelink.light.ceiling3-repacked-stock-2.0.2_0048.bin`.
   Скрипт проверяет MD5 исходника, собирает контейнер через `liblzma-5.dll` (без end-marker, 8-байтное выравнивание `segment 0`), перепроверяет оба SHA-1, trailing CRC32 и подтверждает `segment-0 bytes changed vs stock: 0`.
2. **Этап Б — сборка патченого образа**:
   ```powershell
   python patch_ota.py
   ```
   Результат: `yeelink.light.ceiling3-patched-2.0.2_0048.bin`.
   В логе сборки должны быть выведены все применённые записи `PATCHES`, точное число изменённых байт в `segment 0` (для текущих 3 патчей — 4 байта) и `all container checks OK`.

## 3. Прошивка (OTA) и мониторинг

`miio_ota.py flash` перед запуском HTTP-сервера повторно прогоняет образ через `patch_ota.parse()`, проверяет по `miIO.info`, что `model == 'yeelink.light.ceiling3'`, и логирует все события в `flash.log`.

### Выбор режима отправки `miIO.ota`: `--cloud=de` или локально

- **Если на лампе стоит стоковая `2.0.2_0048`** (без патча #3 в `do_ota`): функция `do_ota` (`0x100f8304`) отклоняет локальный UDP-вызов `miIO.ota` с сообщением `"ota is from local, droped"` (`-30020`). Используйте флаг `--cloud=de` (команда ретранслируется через Xiaomi cloud `/home/rpc/<did>` после QR-входа, но сам файл лампа всё равно скачивает с локального ПК по HTTP на порту `80`).
- **Если на лампе уже стоит патченый образ с патчем #3** (`0x100f831c: 13d4 -> 13e0`): локальный вызов `miIO.ota` работает напрямую без `--cloud`.

### Стадия 1 (опционально): тестовая прошивка переупакованного стока

Рекомендуется при первой проверке нового хоста/окружения, чтобы отдельно убедиться, что загрузчик лампы принимает нашу перепаковку `liblzma`:

```powershell
python miio_ota.py flash yeelink.light.ceiling3-repacked-stock-2.0.2_0048.bin --cloud=de
```

Когда скрипт выведет `serving http://<host_ip>/<md5>.bin` и спросит `press Enter to send miIO.ota to the lamp (Ctrl+C to abort)`, нажмите `Enter` (флаг `--yes` используйте только в осознанном ручном запуске, когда все проверки пройдены).

### Стадия 2: прошивка патченого образа

```powershell
python miio_ota.py flash yeelink.light.ceiling3-patched-2.0.2_0048.bin --cloud=de
```
*(Если на лампе уже установлен патченый образ с фиксом `do_ota`, `--cloud=de` можно опустить.)*

### Мониторинг процесса

- `miio_ota.py flash` автоматически опрашивает `miIO.get_ota_state`, `miIO.get_ota_progress` и `miIO.info` (`life`) каждые 3 секунды (до 10 минут), отслеживает завершение HTTP-передачи (`downloaded_by`) и фактическую перезагрузку по падению uptime (`life < life0 - 5`), игнорируя одиночные потери UDP-пакетов.
- В отдельном терминале можно контролировать состояние вручную и вести пассивный лог:
  ```powershell
  python miio_ota.py state
  python monitor_lamp.py
  ```
- Все этапы прошивки записываются в flash.log.

## 4. Восстановление и откат при регрессии

### 4.1. Поведение при тёплой перезагрузке (`cmd.reboot` / `yglc_network_monitor`)

- При срабатывании патченого `yglc_network_monitor` (5 минут без IP независимо от того, включён ли свет) вызывается `cmd_reboot` (`FUN_100f81e4` -> `FUN_100bed64(0)`).
- Текущее состояние света сохраняется в `yl_cache` (`0x3ba000`) с маркером `0xdeadbeef` (`type = 1`), восстанавливается функцией `FUN_100c32fc()` после загрузки и **не увеличивает** счётчик `fast_reboot_count`. Это предотвращает ложный сброс сопряжения с Mi Home.

### 4.2. Программный откат на сток

Если лампа загрузилась, отвечает по сети (`miio` / облако) и принимает команды, откатите её на оригинальный сток тем же OTA-скриптом:

```powershell
python miio_ota.py flash yeelink.light.ceiling3-stock-2.0.2_0048.bin
```
*(Если локальный `miIO.ota` не принимается — добавьте `--cloud=de`.)*

### 4.3. Сброс сопряжения (Mi Home re-pair reset)

Если сбилась конфигурация Wi-Fi или токен/NVDM-параметры:
1. Выполните стандартный аппаратный сброс Yeelight (5 быстрых циклов включения/выключения питания по 2 секунды, до световой индикации/пульсации).
2. Заново добавьте светильник в приложении Mi Home.
3. После повторного сопряжения токен устройства изменится — обновите `token.txt` командой `python xiaomi_qr_token.py de`.

### 4.4. Аппаратный откат (UART / SWD) и ограничения

> [!WARNING]
> **В репозитории нет полного дампа flash (full flash dump).**
> Стоковый OTA-контейнер (`yeelink.light.ceiling3-stock-2.0.2_0048.bin`) содержит только 3 раздела: сегмент 0 (`0x71000` — CM4 app), сегмент 1 (`0x8000` — N9) и сегмент 2 (`0x20a000` — трамплин). Загрузчик, таблица разделов и разделы NVDM/factory/calibrations в OTA не входят.

Если после неудачной модификации лампа ушла в bootloop или перестала выходить на связь по Wi-Fi (и 5-кратный сброс питания не переводит её в режим настройки):
- Единственный путь восстановления — разборка светильника и прямое подключение к модулю MediaTek MT7697N по **UART** (через `mt76x7-uploader` / бут-режим загрузки) или **SWD**.
- Заливать через UART можно только соответствующие адреса flash (`0x8000`, `0x71000`, `0x20a000`) из `extracted/`, **не затирая** области загрузчика и NVDM/Wi-Fi калибровок (перед любой записью по UART/SWD обязательно снимите полный бэкап flash с чипа).
